# 5주차 문서 청킹·TF-IDF·벡터 검색 실험

**목표:** 동일한 8개 짧은 문서를 나누고 질문 20개로 검색·점수·원문 위치·Recall을 확인한다.

수행 방식: **PC 웹 데모 + 실제 검색·평가 계산**. 주 5일·하루 6시간, 총 30시간이다. 아래 순서와 기준 설정으로 먼저 완료하고 확장은 그다음에 한다.

[입력 자료](DATA.md) · [참고 링크](RESOURCES.md) · [완료 체크](CHECKLIST.md)

## 1. 시작 전 준비와 기준 설정

1. inputs/corpus.json은 Python 개념을 설명하려고 직접 작성한 짧은 문단 8개다. 공식 문서 전체 snapshot이 아니다. inputs/dev_questions.json에는 답 가능 15개·근거 없음 5개와 정답 문서 ID가 있다.
2. 기준 chunk_size=90 Unicode 문자, overlap=20, top_k=3, 문서 순서 D01~D08. 원문 위치는 0-based, 끝 위치는 exclusive다. 마지막 조각을 만든 뒤 중복 꼬리 chunk를 추가하지 않는다.
3. 실제 TF-IDF는 문자 2~4 gram, smooth idf=ln((1+문서 조각 수)/(1+df))+1, raw tf, L2 정규화, cosine이다. 동점은 원래 chunk 순서를 유지한다.
4. 비교 벡터는 3개 keyword 범주를 세어 정규화한 교육용 벡터다. 신경망 sentence embedding·사전학습 모델을 실행한 것이 아니다. corpus·질문·설정을 맞추어 두 계산 방식을 비교한다.

웹 파일은 이 폴더의 **[demo.html](demo.html)**이다. PC에서 더블클릭하거나 브라우저의 파일 열기로 연다. 서버·설치·API 키 없이 작동한다. 화면에서 실험하고 내려받은 JSON을 결과 폴더에 모은다.

## 2. 기준 실행 흐름

```text
demo.html 열기 → 크기 90·overlap 20 → TF-IDF → Q01 → 검색 실행 → 20개 평가 → 결과 저장
```

입력 준비 → 일별 작업 → 결과 파일 생성 → 정상·실패 비교 → 보고서 순서로 진행한다.

## 3. 1일차 · L21 입력 문서와 개발 질문 확인

### 1-1. 수행

inputs/corpus.json의 8개 문서를 읽고 doc_id·제목·본문·참고 URL을 확인한다.

- **나와야 할 것:** 문서 목록과 corpus 범위 설명
- **확인 방법:** 작성한 문단과 공식 문서 snapshot을 구분한다.

### 1-2. 수행

개발 질문 20개를 읽고 정답 문서·기대 답변·근거 없음 표시를 확인한다.

- **나와야 할 것:** 개발 질문 분류 표
- **확인 방법:** 답 가능 15개와 근거 없음 5개인지 센다.

### 1-3. 수행

웹 데모에서 D01 원문과 기준 질문 Q01을 확인한다.

- **나와야 할 것:** 기준 입력 관찰 기록
- **확인 방법:** 문서·질문 순서와 ID를 바꾸지 않는다.

## 4. 2일차 · L22 고정 규칙으로 청킹

### 2-1. 수행

크기 90·overlap 20으로 인덱스를 구성하고 각 chunk의 ID·문서·시작·끝·본문을 확인한다.

- **나와야 할 것:** chunks.jsonl 또는 웹 export의 chunks
- **확인 방법:** 본문이 원문[start:end]와 정확히 같아야 한다.

### 2-2. 수행

overlap을 0으로 바꾸고 chunk 수·연결 부분을 비교한 뒤 기준 20으로 복구한다.

- **나와야 할 것:** chunk_comparison.csv
- **확인 방법:** 겹치는 문자가 무엇인지 직접 표시하고 0≤overlap<chunk_size를 확인한다.

### 2-3. 수행

같은 청킹을 작은 Python 함수로 직접 수행한다. 빈 문서·너무 큰 overlap도 확인한다.

- **나와야 할 것:** chunk_checks.json
- **확인 방법:** 문자 수를 embedding token 수로 표현하지 않는다. 실제 모델의 token 절단 검사는 이번 범위가 아니다.

## 5. 3일차 · L23 교육용 cosine 계산과 top-3

### 3-1. 수행

q=[1,0,0], 문서 벡터 [[1,0,0],[0.8,0.6,0],[0,1,0]]의 cosine을 NumPy로 구한다.

- **나와야 할 것:** cosine_math.json
- **확인 방법:** 점수 [1,0.8,0], 순서 [0,1,2]를 대조한다.

### 3-2. 수행

웹 데모에서 3차원 교육 벡터 방식을 선택해 질문·chunk 벡터와 점수를 확인한다.

- **나와야 할 것:** vector_search.json
- **확인 방법:** 이 벡터가 어떤 keyword 범주를 세었는지 설명한다.

### 3-3. 수행

top-3를 원문 위치와 대조한다. zero vector의 점수는 0으로 처리하는 규칙을 기록한다.

- **나와야 할 것:** 검색 결과와 근거 확인 기록
- **확인 방법:** 정답 문서를 찾았다는 것과 필요한 근거가 chunk에 있다는 것을 구분한다.

## 6. 4일차 · L24 실제 TF-IDF와 벡터 방식 비교

### 4-1. 수행

같은 Q01에서 TF-IDF와 3차원 벡터 방식의 순위·점수를 비교한다.

- **나와야 할 것:** retrieval_comparison.csv
- **확인 방법:** 서로 다른 점수 체계의 숫자를 같은 확률로 해석하지 않는다.

### 4-2. 수행

Q01을 같은 뜻의 다른 표현으로 바꾸고 기준 질문 결과와 비교한다.

- **나와야 할 것:** 표현 변경 사례
- **확인 방법:** 바뀐 질문은 개발셋 기준 지표와 별도의 추가 실험으로 기록한다.

### 4-3. 수행

근거 없는 Q16도 검색해 결과가 나오는지 본다.

- **나와야 할 것:** 근거 없음 검색 사례
- **확인 방법:** top-3가 존재한다고 문서에 정답이 있다는 뜻은 아니다.

## 7. 5일차 · L25 20개 질문 Recall과 설정 저장

### 5-1. 수행

기준 설정으로 20개 평가를 실행하고 질문별 top-3와 Recall을 저장한다.

- **나와야 할 것:** retrieval_results.json, retrieval_metrics.json
- **확인 방법:** 상위 3개 chunk의 doc_id 중복을 제거하고 정답 문서 집합과 비교한다.

### 5-2. 수행

답 가능한 15개만 Recall 평균에 넣고 근거 없는 5개는 N/A로 표시한다.

- **나와야 할 것:** 질문별 계산과 집계
- **확인 방법:** 정답 문서 2개 중 1개면 Recall 0.5다. 질문 평균의 분모 15를 기록한다.

### 5-3. 수행

chunk 크기 한 가지만 바꿔 실패 사례와 개선·악화를 확인한 뒤 기준 설정 결과를 보관한다.

- **나와야 할 것:** manifest.json, 추가 실험 보고
- **확인 방법:** corpus ID·청킹·검색 방법·정규화·동점 규칙을 저장한다.

## 8. 제출 파일과 확인 기준

| 파일 | 내용·필드 | 확인 기준 |
| --- | --- | --- |
| chunks.jsonl / chunk_checks.json | chunk_id, doc_id, start, end, text | 원문 slice 일치·빈 조각 없음 |
| cosine_math.json | 입력 벡터·점수·순위 | [1,0.8,0] 재계산 |
| retrieval_results.json | 질문별 top-3·점수·문서·원문 위치 | 동일 기준 설정에서 같은 순위 |
| retrieval_metrics.json / retrieval_comparison.csv | 질문별 Recall·평균·포함/제외 수 | 20개 중 15개 포함·5개 제외 |
| manifest.json | corpus, chunk_size, overlap, top_k, method, vector_kind | 신경망 embedding이 아니라고 명시 |
