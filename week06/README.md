# 6주차 RAG 연결 벡터 저장소와 최종 평가

이번 주 실습은 **근거를 제시하는 문서 질문 응답 RAG CLI**입니다. 대응 ID는 L26~L30, 계획시간은 30시간입니다.

[참고 자료](RESOURCES.md) · [데이터와 모델 링크](DATA.md) · [체크리스트](CHECKLIST.md)

## 과제

5주차 직접 계산한 검색을 Chroma의 로컬 영속 저장소로 옮깁니다. 직접 만든 embedding과 metadata를 저장하고 별도 프로세스에서 로드해 검색합니다. 문서·질문의 embedding 모델과 차원, 정규화 및 거리 설정이 맞는지 확인합니다.

질문→embedding→top-3 검색→context 구성→LLM 생성→근거 출력의 전체 흐름을 직접 연결합니다. 생성에 넣은 chunk와 답변의 문서·chunk ID를 함께 기록합니다. 검색 문서는 데이터로 취급하며 문서에 포함된 지시가 시스템의 동작을 바꾸지 않도록 확인합니다.

문서에서 확인할 수 없는 질문에는 근거 부족을 표시하는 동작을 구현합니다. 거절 조건과 점수 기준을 사용한다면 개발셋에서 결정하고 최종 평가에서 바꾸지 않습니다. 모델이 만들어낸 출처를 그대로 출력하지 않고 실제 context와 대조합니다.

중복 인덱싱, 원문 변경 뒤 재인덱싱, 빈 질문, 검색 실패, 긴 context와 생성 실패를 확인합니다. build-index, search, answer, evaluate 역할을 각각 실행할 수 있도록 CLI를 정리합니다. 함수와 명령 이름은 직접 정합니다.

개발셋에서 설정을 확정하고 교육자가 보관한 최종 질문 10개를 처음 평가합니다. 검색 없는 LLM, TF-IDF RAG, dense RAG를 동일 질문·모델·생성 조건에서 비교하고 prompt 차이가 있다면 명시합니다. 정답성·인용 근거·근거 없는 질문 거절·지연과 검색 Recall을 보고합니다.
