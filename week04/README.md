# 4주차 토이 프로젝트 완성

이번 주에는 앞서 만든 과제 하나를 선택해 다른 사람이 실행할 수 있는 프로젝트로 정리합니다. 입력과 출력, 실행 기능, 오류 처리, 평가 결과와 한계를 설명하는 것이 목표입니다.

대응 작업은 L16~L20입니다. [참고 자료](RESOURCES.md), [데이터 링크](DATA.md), [목표 체크리스트](CHECKLIST.md)를 확인하세요.

## 과제

Titanic 분류 또는 FashionMNIST MLP를 선택하세요. 2주차에 Wine으로 대체했다면 그 분류 프로젝트도 선택할 수 있습니다. 새 데이터나 서비스를 추가하기보다 기존 작업을 완성합니다.

[프로젝트 계획 양식](../templates/PROJECT_PROPOSAL.md)에 입력, 출력, 실패 동작과 완료 기준을 적고 작은 개선 한 가지를 선택합니다. 교육자와 범위를 확인한 뒤 구현하세요.

학습, 평가, 예측 기능은 터미널에서 각각 실행할 수 있어야 합니다. 경로와 주요 설정을 실행 인자로 지정하고 저장한 모델을 예측에 재사용합니다. 파일을 세 개로 나눌지 하나의 CLI에 기능을 나눌지는 직접 정합니다.

## 개선과 비교

기존 버전과 개선 버전을 같은 validation 조건에서 비교하세요. 개선은 전처리, 작은 모델 설정, 오류 처리, 재현성 또는 실행시간 중 하나를 선택할 수 있습니다. 개선 효과가 없거나 성능이 낮아졌어도 측정과 원인 분석이 정확하면 결과로 인정됩니다.

실행시간 비교는 데이터 수, 장치, 측정 구간과 반복 조건을 기록합니다. 데이터 다운로드나 최초 실행 비용을 포함했는지도 밝혀야 합니다. 최종 평가 전에 모델과 설정을 확정합니다.

## 완료 조건

- 데이터 확보와 환경, 실행 위치를 README에서 확인할 수 있다.
- 학습, 평가, 예측을 각각 실행할 수 있다.
- 저장한 모델을 별도 실행에서 불러와 예측한다.
- 정상 입력과 실패 입력을 재현하고 결과를 설명한다.
- 개선 전후를 동일 조건에서 비교했다.
- 다른 사람이 README를 보고 실행한 결과와 수정 사항을 남겼다.
- 남겨둔 holdout 또는 공식 test로 확정한 모델의 최종 결과와 한계를 보고한다.

다른 사람의 실행은 교육자나 동료와 시간을 정해 진행합니다. 실행할 사람이 없다면 교육자에게 알리고 새 작업 폴더와 새 환경에서 재현한 기록을 제출하되, 다른 사람의 실행은 미확인으로 표시합니다.

## 최종 평가

Titanic 또는 Wine은 앞서 남긴 holdout, FashionMNIST는 공식 test를 사용합니다. 이미 최종 평가 데이터를 모델 선택에 사용했다면 최종 평가라고 표현하지 말고 교육자에게 평가 조건을 다시 확인받으세요.

최종 결과를 본 뒤 조정한 모델은 같은 최종 평가 데이터에서 얻은 수치를 독립적인 최종 평가로 주장하지 않습니다. 어떤 데이터가 무엇에 사용됐는지 보고합니다.

## 제출

프로젝트 계획, 전체 코드, 실행 README, 검증표, 개선 비교, 리뷰 반영 내용과 [주간 보고서](../templates/WEEKLY_REPORT.md)를 제출합니다. 모델 바이너리 대신 저장·로드 방법과 확인 근거를 남기세요.

웹 UI, API 서버, Docker, 배포, 대규모 튜닝은 필수 범위에 포함하지 않습니다. 필수 완료 조건을 마친 뒤 다음 과제로 정할 수 있습니다.
