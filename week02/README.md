# 2주차 Titanic 머신러닝 전체 흐름

이번 주에는 Titanic 생존 예측을 통해 데이터 분할, 전처리, baseline, 모델 비교, 저장과 재사용을 연결합니다. 높은 대회 순위보다 평가 조건과 데이터 흐름을 설명할 수 있는 것이 목표입니다.

대응 작업은 L06~L10입니다. [참고 자료](RESOURCES.md), [데이터 링크](DATA.md), [목표 체크리스트](CHECKLIST.md)를 확인하세요.

## 과제

Titanic 데이터를 확보하고 입력, 정답, ID와 파일별 역할을 설명하세요. 정답이 있는 데이터에서 train, validation, 최종 holdout을 미리 나누고 분할 규칙과 seed를 기록합니다. 최종 holdout은 모델과 전처리 선택이 끝날 때까지 사용하지 않습니다. 이번 주의 모델 비교는 validation에서 합니다.

전체 열의 의미와 파일 형식을 확인한 뒤, 전처리와 모델 선택에 영향을 주는 상세 탐색은 train을 중심으로 수행하세요. 결측, 범주와 숫자 열을 어떻게 처리할지 직접 결정합니다. 전처리의 fit은 train에만 수행하고 validation과 예측 데이터에는 같은 변환을 적용합니다.

DummyClassifier baseline, LogisticRegression, 작은 DecisionTreeClassifier를 같은 분할에서 비교하세요. 전처리와 모델을 Pipeline으로 묶고 필요한 열별 처리를 구성합니다. 모델별 설정과 평가 지표 선택의 이유를 기록하세요.

선택한 Pipeline을 저장한 뒤 별도 실행에서 불러와 예측 CSV를 생성합니다. Kaggle 제출은 선택입니다.

## 결과에 포함할 내용

- 입력 열, 정답 열과 ID를 구분한 데이터 설명
- train을 중심으로 작성한 결측·자료형·분포 요약
- 분할의 크기, seed와 재현 가능한 규칙
- baseline과 모델 2개의 동일 조건 비교표
- confusion matrix와 오류 사례의 해석
- 저장·재로드 전후 예측 일관성 확인
- 예측 CSV의 열, 행 수, ID 대응 확인

Kaggle용 예측 파일은 `PassengerId`와 `Survived` 열을 가져야 하며, 각 입력 ID에 대응하는 예측을 담아야 합니다. 파일의 값과 형식은 대회 데이터 설명에서 확인하세요.

## 스스로 확인할 조건

분할 간 같은 행이 중복되지 않았는지 확인하세요. ID나 정답 열을 입력에 포함했는지, 결측 처리나 인코딩을 어느 데이터에 맞췄는지 설명합니다. 재로드 비교에는 같은 입력을 사용하세요.

평가 데이터의 정확도를 반복 확인해 모델을 고르는 과정이 있으면 그것이 최종 holdout인지 검토하세요. 성능 목표를 임의로 맞추기보다 평가 절차와 결과를 정확히 보고합니다.
