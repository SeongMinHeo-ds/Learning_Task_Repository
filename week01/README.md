# 1주차 Wine 데이터 처리와 개발 도구

이번 주에는 Wine 데이터를 읽고 요약·필터링·저장하는 프로그램을 만듭니다. 가상환경, 터미널, Bash, Python 코드 구조와 Git을 실제 작업에 사용하고, 코드의 입력과 출력을 설명하는 것이 목표입니다.

대응 작업은 L01~L05입니다. [참고 자료](RESOURCES.md), [데이터 링크](DATA.md), [목표 체크리스트](CHECKLIST.md)를 확인하세요.

## 과제

Wine 데이터를 확보하고 열의 의미를 확인하세요. 입력 파일을 읽어 데이터 요약을 JSON으로 저장하고, 사용자가 선택한 숫자 열과 임계값을 기준으로 행을 선택해 CSV로 저장하는 프로그램을 작성하세요. 선택 조건은 해당 열의 값이 임계값 이상인 경우로 합니다.

사용자는 실행할 때 입력 경로, 출력 위치, 숫자 열, 임계값을 지정할 수 있어야 합니다. 옵션 이름과 코드 구조는 직접 정합니다. 출력에는 해석 가능한 열 이름이 있어야 합니다.

Python 실행 환경과 현재 작업 위치를 확인하는 작은 Bash 스크립트를 직접 작성해 실행하세요. 참고 자료의 예제를 읽고 필요한 부분을 바꾸어도 됩니다. 최종적으로 데이터 처리 프로그램을 실행하는 Bash 스크립트도 작성합니다.

## 결과에 포함할 내용

- 원본 행·열 수, 열별 자료형과 결측 개수, 숫자 열 요약을 담은 JSON
- 선택 조건과 원본 행의 관계를 확인할 수 있는 결과 CSV
- 역할을 나눈 함수와 모듈, CLI 인자를 받는 실행 기능
- Bash 스크립트의 목적과 실제 실행 기록
- 파일 없음, 존재하지 않는 열, 숫자가 아닌 임계값의 처리 결과
- 사용한 데이터 출처, 환경, 실행 방법과 변경 이유

list, dict, tuple, set 중 실제 사용한 자료구조의 선택 이유를 설명하고 다른 선택과 차이를 짧게 정리하세요. 과제를 위해 모든 자료구조를 억지로 사용할 필요는 없습니다. 함수의 인자와 반환값, import, 실행 시작점, 사용하는 라이브러리 객체의 역할도 설명합니다.

## 스스로 확인할 조건

같은 입력과 조건이면 같은 행이 선택되어야 합니다. 선택된 행의 값이 조건을 만족하는지 원본과 대조하세요. 입력을 바꾸거나 선택 결과가 0행인 경우도 확인합니다. 오류를 조용히 무시하거나 실패했는데 정상 결과처럼 저장하지 않도록 동작을 정하세요.

정상 원본의 작은 복사본에서 값을 바꾸어 잘못된 데이터 입력을 직접 만듭니다. 변경한 항목과 프로그램의 기대 동작을 보고서에 적습니다. 원본 파일은 보관합니다.

## 제출

코드, Bash 스크립트, 실행 설명, 작은 결과 예시와 오류 기록을 제출합니다. [주간 보고서 양식](../templates/WEEKLY_REPORT.md)에 L01~L05의 증빙 경로를 적으세요. 새 터미널에서도 자신의 실행 설명으로 재현할 수 있어야 합니다.

원본 데이터와 가상환경은 Git에 넣지 않습니다. 노트북은 탐색에 사용할 수 있지만 최종 데이터 처리 기능은 터미널에서 실행합니다.
